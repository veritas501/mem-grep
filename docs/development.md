# Development

## Layout and rules

Code lives in packages: the entry point in `cmd/mg`, everything else under `internal/<package>` (see [architecture.md](architecture.md)); no `.go` files at the repository root.

- **Go ≥ 1.24.** Dependencies are kept few and pinned so that neither they nor their dependencies need a newer Go: `modernc.org/sqlite` (pure Go, no cgo; reads opencode's database), `klauspost/compress` (zstd; Codex's compressed rollouts), `spf13/cobra`. Check a new dependency's `go` directive before adding it; `go.mod` must stay at `go 1.24.0`.
- **Output** goes to stdout, warnings and errors to stderr (`mg: warning: …`).
- **Redact** (`util.Redact`) every text before it is printed; matching may run on unredacted text only if candidates are redacted and matched again.
- **Offline and stateless:** no model, no network, no index or cache file.

## Make targets

`make` is the only build entry point.

| Target | Does |
|---|---|
| `make build` | `bin/mg` with the version injected |
| `make install` | Build and install to `$(PREFIX)` (default `~/.local/bin`) |
| `make run ARGS="docker 网络"` | Run from source with the version injected, reading your real sessions |
| `make test` | `go test ./...` |
| `make lint` | gofmt check, `go vet`, golangci-lint (`.golangci.yml`; must report 0 issues) |
| `make version` | Build and print the injected identity |
| `make clean` | Remove `bin/` |
| `make docker` | Build image `$(IMAGE):$(IMAGE_TAG)` (default `mem-grep:dev`) |
| `make bump BUMP=patch` | Cut a release (below) |

## Version

Git is the only source of the version. The Makefile computes

```make
VERSION ?= $(shell git describe --tags --always --dirty 2>/dev/null || echo dev)
COMMIT  ?= $(shell git rev-parse --short HEAD 2>/dev/null || echo none)
BUILT   ?= $(shell date -u +%Y-%m-%dT%H:%M:%SZ)
```

and injects them with `-ldflags -X` into package variables of `internal/version` — no generated file, no edited constant. `build`, `install`, `run` and `dev` share the same flags. The binary reports itself in one line:

```
$ mg version
mg v1.2.3-4-gabc1234-dirty (commit=abc1234, built=2026-07-21T09:00:00Z)
```

- On a tag: `v1.2.3`; after it: `v1.2.3-N-g<hash>`; without tags: the short commit; uncommitted changes add `-dirty`.
- Without git metadata (e.g. a `git archive` export) the Makefile falls back to `dev` / `none`.
- An uninjected build (`go run ./cmd/mg`, plain `go build`, `go test`) reports `dev (commit=none, built=unknown)`, so a missing injection is obvious.
- `VERSION`, `COMMIT` and `BUILT` can be overridden from the environment.

## Releases

```bash
make bump BUMP=patch        # or minor, major, or an explicit vX.Y.Z
```

`scripts/bump-version.sh` does one self-contained transaction and never pushes:

1. commits pending changes (`git add -A`; message from `BUMP_MESSAGE`, default `chore: pending changes before vX.Y.Z`);
2. creates a release commit with version metadata only — it changes no files, since there is no version file;
3. creates an annotated tag whose message groups the commits since the previous tag into **Features** (`feat:`, or subjects starting with add / implement / support), **Fixes** (`fix:`) and **Maintenance** (everything else), ending with `Version: OLD -> NEW`.

It refuses an existing tag. Push with `git push origin HEAD && git push origin vX.Y.Z`.

## Docker and CI

The Dockerfile builds the static binary (`CGO_ENABLED=0`) into a distroless image; the entry point is `mg`, so mount session directories read-only and pass them with `--path`. It never runs git: `VERSION`, `COMMIT` and `BUILT` arrive as build args (`make docker` passes them) and default to `dev` / `none` / `unknown`. The image tag (`IMAGE_TAG`, default `dev`) is independent of the injected version.

CI (`.github/workflows/ci.yml`) checks out full history (for `git describe`), sets up Go from `go.mod`, runs golangci-lint, computes the identity once into the environment, then runs `make lint`, `make test`, `make version`, and builds the image and runs `version` in it.

## Tests and fixtures

- omp fixtures in `test/fixtures/sessions/` were written by omp's own `SessionManager`; regenerate them with `test/fixtures/gen-fixtures.ts` (needs bun and the omp package; usage in its header) and update the tests that assert entry ids and counts (`internal/sources`, `internal/grep`, `internal/cli/mg`).
- Fixtures for other agents must also be generated by the agent itself, never hand-written or copied from a real session. Gemini CLI, Qwen Code and opencode have them: `test/fixtures/{gemini,qwen,opencode}/gen.sh` install nothing themselves — install the CLI first (`npm install --prefix <dir> @google/gemini-cli | @qwen-code/qwen-code | opencode-ai`, then run opencode-ai's `postinstall.mjs`; versions are in each script's header) and pass its binary, e.g. `PATH=<dir>/node_modules/.bin:$PATH test/fixtures/qwen/gen.sh`. Each script starts `test/fixtures/gen/mock-model.mjs` (a scripted model that speaks the OpenAI and Gemini protocols; no account, credential or real model), runs the agent in a throwaway `HOME` through a few scenarios (tools that succeed and fail, a resumed session, a subagent) and copies the session files into the fixture directory. Regenerate after an agent upgrade to see whether its format changed; the tests assert on structure, not on ids, times or directory listings. `test/fixtures/real/gen.sh gemini|qwen|opencode` does the same against a real model (DeepSeek's OpenAI-compatible API) for a small bug-fixing task in two prompts: `DEEPSEEK_API_KEY=… test/fixtures/real/gen.sh qwen`. The key lives only in the environment (the script hands it to the agent, or for Gemini to `test/fixtures/gen/gemini-to-openai.mjs`, a translator from Gemini's protocol to the OpenAI one, and refuses to finish if any output contains `sk-` or the key). Behind an egress proxy the script passes `HTTPS_PROXY`, `SSL_CERT_FILE` and `NODE_EXTRA_CA_CERTS` on. These sessions differ on every run, so `internal/sources/realfixtures_test.go` asserts only invariants (two turns, every tool call paired with its own result, no agent-side wrappers, offsets in range); regenerate them rarely and review the diff. CLIProxyAPI was not needed: the agents talk to the upstream directly. Claude Code and Codex have no fixtures yet, so only mem-grep's own rules are unit-tested for them (`internal/sources/codex_test.go`).
- mg's tests use the omp fixtures through `--path`. `TestSearchEqualsReference` compares the optimised search with a plain one (decode everything, regexp every line) for every query shape; `TestEarlyStopReturnsTheNewestHits` does the same on copies of the fixture spread over 40 days. For performance work, generate a large corpus with omp's `SessionManager` (as `gen-fixtures.ts` does) rather than copying real sessions, and run the comparison on it with `MG_CORPUS=<dir> go test ./internal/grep -run OnCorpus`; spread the sessions' dates and mtimes over months to exercise the early stop. Numbers so far: [mem-grep.md](mem-grep.md#performance).
- Try the CLI against the fixtures: `make run ARGS="docker --path test/fixtures"`. Tests that must not see the machine's own sessions point `HOME` and the `MG_*` variables at a temporary directory (`internal/config` and `internal/cli/mg` do).
